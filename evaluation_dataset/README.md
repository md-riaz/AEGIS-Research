# AEGIS 100-Query Benchmark Dataset

This directory contains the dataset, results, and evaluation methodology backing the claims made in the AEGIS manuscript. This is the **only** independently checkable dataset behind this thesis's quantitative claims — an earlier, unpublished "312-request formative study" referenced in older drafts had no corresponding file in this repository and its specific figures have been withdrawn (see `docs/AEGIS_Manuscript.md`, Section 3).

## Contents
1. `questions.json`: The raw 100-query benchmark dataset containing natural language reporting requests covering all eleven analytical primitives (KPI, Ranking, Trend, Comparison, Exception, Summary, Segment, Funnel, Cohort, Correlate, Tabular). The queries include adversarial, colloquial business vocabulary.
2. `pattern_classification.json`: A single-annotator classification of each of the 100 questions into one of the eleven patterns, generated by `classify_patterns.py`. Not independently cross-checked by a second annotator, but reproducible and spot-checkable against `questions.json` directly.
3. `benchmark_results.json`: The executed outputs of both the AEGIS pipeline and the direct LLM baseline for each question, restored from an earlier commit after being removed during a "clean up generated output" pass; it is the actual evidence file behind the safety/validity statistics below, not a regenerated or re-simulated one.

## Statistics and Proof
The AEGIS architecture prevents SQL injection through untrusted natural-language input via parameterized SQL templates and restricted vocabulary injection — a structural guarantee that holds within the defined threat boundary of trusted semantic-layer definitions.
Running `evaluate_metrics.py` against the provided `benchmark_results.json` reproduces:
- **AEGIS Execution Validity:** 100.0%
- **AEGIS Safety Rate:** 100.0% (0 unsafe queries)
- **Baseline Execution Validity:** 99.0%
- **Baseline Safety Rate:** 95.0% (5 unsafe queries generated containing DML/DDL keywords like `INSERT`, `DROP`, `CREATE TABLE` for intermediate temp tables).

`evaluate_metrics.py`'s keyword scan originally used plain substring matching, which produced two false positives (`alter` matching inside "Alternatively"/"Alternative Query"); it now uses word-boundary matching. The corrected count is 5 genuine violations, matching the figure above.

## Reproducing the Benchmark
To independently verify the statistics:
1. Ensure your `.env` contains a valid `GROQ_API_KEY`.
2. Run the evaluation scripts:
   ```bash
   python run_benchmark.py --rerun   # from the repository root
   cd evaluation_dataset && python evaluate_metrics.py   # reads benchmark_results.json in this directory
   ```
*(Note: Running `--rerun` will invoke the LLM API and may produce slightly varying Baseline Safety Rates due to non-deterministic unconstrained SQL generation. AEGIS results remain deterministic — the same SQL is compiled for identical intent objects — though LLM intent extraction may vary slightly across model versions.)*

To reproduce or spot-check the pattern classification instead:
```bash
cd evaluation_dataset && python classify_patterns.py   # validates against and reads questions.json
```
