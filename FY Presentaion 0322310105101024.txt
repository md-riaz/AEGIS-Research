Problem Statement
Although NLP-to-SQL, conversational Business Intelligence, and natural-language-to-visualization research have advanced significantly, most prior systems solve only part of the full analytics pipeline.
Unsafe & Unscalable: Raw SQL exposes sensitive data, is hard to cache, and unpredictable in performance.
Unpredictable & Unstructured: Free-form AI-generated SQL may violate application-level constraints, produce expensive queries, or ignore business-safe definitions.
Ambiguous Questions: Users struggle to express intent without knowing the data model or SQL language
Lack of Persistence: Many prior research works focus on query generation or visualization, but not on persistent reusable dashboard widgets.
There is still no complete, safe, end-to-end workflow that converts natural-language business requests into reusable dashboard widgets. 
Most prior systems solve one layer only. Some convert text to SQL. Some generate dashboards. Some support conversation. But very few combine safe query control, business meaning, and reusable dashboard outputs in one pipeline

What This Thesis Proposes
The thesis proposes a constraint-based natural language reporting system.
The core idea is:
AI is used for understanding the question
the system, not the AI, controls how the query is executed
Instead of generating unrestricted SQL directly, the system creates a structured analysis plan first.
That plan is then compiled using:
approved metrics
approved dimensions
known relationships
safe query patterns
The final output becomes a widget-ready result such as a KPI, table, or chart.
LLM for interpretation, system rules for execution.

Methodology
Data flows from left to right: the LLM parses queries, semantics map terms, the plan builder structures the analysis, the compiler creates safe SQL, the executor runs queries, the visualizer chooses charts, and the widget engine saves the output.

System Architecture
Use a known relational schema (e.g., university management system).
Define the semantic layer: metrics, dimensions, filters, time rules and join definitions.
Define a pattern library: ranking, trend, comparison, aggregation, segmentation.
Integrate an existing LLM API for intent extraction, constrained to return structured JSON only.
Build the safe query compiler and widget engine.
Design user tasks representing typical reporting needs and run controlled experiments.
Evaluate accuracy of intent parsing, mapping validity, SQL correctness, response time, visualization suitability and user satisfaction.

Where AI is truly free (and should be)
AI can:
rephrase intent
infer missing context
choose best metric
decide chart type
suggest follow-ups
explain results in natural language

AI cannot:
invent joins
bypass permissions
hit raw tables
create unbounded queries
AI has freedom in interpretation, not execution.
Freedom of thinking, not acting.
